## Deliverable

A reproducibly built Windows app-image folder containing:
- AroNexaClinicShell.exe native Windows launcher generated by jpackage, with a bundled Java 21 runtime.
- A compiled production-source Spring Boot JAR (included, but intentionally NOT started).
- The compiled connected Reception React HTML, JS and CSS.
- An exact source SHA marker and SHA256 file inventory.

The EXE serves only a loopback static interface: http://127.0.0.1:8766/ (no patient database). It does NOT launch Spring Boot or any test-only clinical endpoint; the bundle does not require Git, Maven, Node or Docker to show the static shell after packaging. Production authentication, booking, clinical Rx and billing are disabled here. The compiled Reception interface can be viewed but not used for clinical work.

HTTP GET /healthz returns 200 with clinicalReady=false; GET /api/v1/... returns 503 CLINICAL_API_NOT_AUTHORIZED, while POST and unsupported methods return 405. The static file server refuses path traversal, symlinks, sensitive files, external binding and unrecognized assets. It sets no-store, nosniff, CSP, frame and referrer response headers.

The manifest detects inadvertent artifact changes; it is NOT a publisher cryptographic signature, safe updater or independent supply-chain audit.

## Source files

- scripts/windows-runtime/ClinicWindowsShell.java: Java21 localhost HTTP server, file-hash checks and loopback/API-denial selftest.
- scripts/windows-runtime/Build-AroNexa-WIN11-AppImage.ps1: exact-SHA clean worktree verification; local JDK21, Maven, npm and jpackage build; TypeScript/Node test and compiled frontend; jpackage app-image; real Windows EXE selftest.
- scripts/windows-runtime/Test-AroNexa-WIN11-AppImage-Restart.ps1: launches the real native EXE twice as different Windows OS processes, verifies the same loopback UI and denied clinical APIs, stops only the process it owns and prints source/PIDs.
- docs/phases/OPD_WINDOWS_WIN11_NATIVE_APPIMAGE.md: this handoff and the customer-release distinction.

## How to build and test locally on Windows

Start with a NEW clean detached Git worktree at the **current WIN-11 Draft PR SHA**. Require JDK21 (including jpackage), Maven, Node/npm. No original Windows DB access is performed by the following scripts.

    $sha = "CURRENT_WIN11_PR_SHA"
    powershell.exe -NoProfile -File .\scripts\windows-runtime\Build-AroNexa-WIN11-AppImage.ps1 -ExpectedCommit $sha -DestinationDirectory "$env:USERPROFILE\Downloads"
    if ($LASTEXITCODE -ne 0) { throw "WIN11 build FAILED" }

The builder emits:
- WIN11 NATIVE APPIMAGE SELFTEST PASSED (ONLY if the native EXE and staged Java tests pass)
- WindowsExe=... and WindowsExeSha256=... plus SourceCommit.

Expected app-image directory:

    %USERPROFILE%\Downloads\AroNexaClinicShell-SHA12\AroNexaClinicShell.exe

Then run the real two-process smoke:

    powershell.exe -NoProfile -File .\scripts\windows-runtime\Test-AroNexa-WIN11-AppImage-Restart.ps1 -ExpectedCommit $sha
    if ($LASTEXITCODE -ne 0) { throw "WIN11 restart FAILED" }

Expected final marker **ONLY if actually run successfully**:

    WIN11 NATIVE APPIMAGE TWO-PROCESS RESTART / API DENIAL QA PASSED

Run manually from inside the generated app-image folder:

    .\AroNexaClinicShell.exe --serve

Open http://127.0.0.1:8766/ then press Ctrl+C to end. Do not enter real patient information.
